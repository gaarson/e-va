# Документация: Управление Контекстом (Context Flow)

Данный документ описывает архитектуру и механизмы управления контекстом в фреймворке E-va, реализованные в модулях `context_flow.lua` и `agent.lua`. Система спроектирована для максимизации эффективности использования токенов LLM, обеспечения долгосрочной памяти и гибкой инъекции критической информации.

## 1. Архитектура Контекста

Управление контекстом разделено на два уровня конфигурации:
1.  **`flow_config`**: Настройки, специфичные для потока контекста (лимиты, стратегии инъекции, профили моделей).
2.  **`full_config`**: Глобальная конфигурация проекта (пути, настройки агентов, инструменты).

При инициализации (`M.new`) происходит глубокое слияние (`utils.deep_merge`) дефолтных настроек, пользовательского `flow_config` и выбранного `model_profile` (если указан в `config.context_profile`).

### Основные компоненты состояния:
*   **`history`**: Хранит диалоговую историю для каждого агента (`self.history[agent_name]`).
*   **`knowledge_base`**: Кэш содержимого файлов, загруженных агентом.
*   **`pinned_files`**: Таблица путей файлов, которые нельзя вытеснить из контекста.
*   **`execution_plan`**: Текущий план выполнения задач.
*   **`last_actions`**: Лог последних действий агента для контекстной осведомленности.

## 2. Управление Историей и Базой Знаний

### 2.1 Добавление сообщений
Метод `M:add_message(agent_name, role, content)` добавляет сообщение в историю конкретного агента и немедленно вызывает стратегию обрезки (`prune_history`).

### 2.2 Стратегии Обрезки (Pruning)
Обрезка истории происходит автоматически при добавлении новых сообщений. Реализованы две основные стратегии:
1.  **`fifo_assistant_first`**: Удаляет самые старые сообщения от ассистента, превышающие лимит.
2.  **`squash_large_patches`**: Сжимает большие блоки кода (патчи) в краткие системные заметки, если история превышает лимит токенов.

### 2.3 Сжатие Мутаций (Auto-Squash)
Если включена опция `auto_squash_on_mutation`, метод `M:squash_last_mutation` находит последнее сообщение ассистента, содержащее команду `patch` или `create_file`, и заменяет её содержимое на системную метку:
```text
[SYSTEM MEMORY: Patch applied to 'src/parser.c'.]
```
Это освобождает место в контексте, сохраняя факт изменения файла.

### 2.4 База Знаний (Knowledge Base)
*   `M:add_file(path, content)`: Добавляет файл в кэш и помечает статусом `READ`.
*   `M:pin_file(path)`: Фиксирует файл в памяти. Зафиксированные файлы отображаются в блоке `recency` и не удаляются при очистке контекста.
*   `M:unpin_file(path)`: Снимает фиксацию.

## 3. Сборка Контекста (Prompt Building)

Метод `M:build_context(agent_name, agent_cfg, available_tokens)` отвечает за формирование финального промпта для LLM.

### 3.1 Расчет Бюджета Токенов
1.  **Оценка накладных расходов**: Считаются токены для системного промпта, манифеста инструментов и блока свежести (`recency`).
2.  **Бюджет на историю**: `chat_budget = available_tokens - overhead - 10%_reserve`.
3.  **Загрузка истории**: Сообщения загружаются с конца (самые свежие) до тех пор, пока не будет исчерпан бюджет.

### 3.2 Стратегии Инъекции (Injection Strategies)
Контекст может инжектироваться разными способами, заданными в `flow_config.context_injection.mode`:
*   **`append_to_last_user`**: Добавляет блок контекста к последнему сообщению пользователя.
*   **`system_block`**: Создает отдельное системное сообщение с контекстом.

### 3.3 Блок Свежести (Recency Block)
Метод `M:get_recency_block()` формирует XML-подобный блок, содержащий:
*   Текущий план выполнения (`execution_plan`).
*   Последние действия (`last_actions`).
*   Содержимое зафиксированных файлов (`pinned_files`), если они не были запрошены явно в текущем туре.

### 3.4 Интеграция Изображений
Если загружены изображения (`self.images_loaded`), они форматируются в соответствии со стандартом OpenAI (multimodal format) и прикрепляются к последнему сообщению пользователя.

## 4. Профили Моделей (Model Profiles)

В `flow_config.model_profiles` можно задать специфичные настройки для разных моделей. Например:
```lua
model_profiles = {
    ["claude-3-opus"] = {
        token_estimation = { chars_per_token = 3.5 },
        context_injection = { mode = "system_block" }
    },
    ["gpt-4o"] = {
        token_estimation = { chars_per_token = 3.0 },
        context_injection = { mode = "append_to_last_user" }
    }
}
```
При инициализации агента профиль автоматически применяется к `flow_config`.

## 5. Переход Стадий (Handoff & State Persistence)

### 5.1 Сохранение и Восстановление
*   `M:snapshot()`: Сериализует всё состояние контекста в JSON.
*   `M:load_from_snapshot(json_str)`: Восстанавливает состояние из JSON.

### 5.2 Handoff Memo
Метод `M:generate_handoff_memo(agent_name, agent_cfg)` создает краткую выжимку для передачи следующему агенту. Включает:
*   План выполнения.
*   Принятые решения (`last_actions`).
*   Измененные файлы.
*   Оставшиеся задачи.

### 5.3 Очистка между стадиями
`M:clear_history_for_stage(strategy)` позволяет настроить степень очистки истории:
*   `"full"`: Полная очистка.
*   `"per_stage"`: Оставляет последние N сообщений.
*   `"none"`: Не очищает.

## 6. Гибкость и Оптимизация

### 6.1 Оптимизация Контекста
Инструмент `optimize_context` позволяет агенту динамически управлять памятью:
```json
{
  "remove_files": ["src/old_module.lua"],
  "pin_files": ["src/core.h"],
  "update_summary": "Новая сводка задачи"
}
```

### 6.2 Инъекция Файлов при Handoff
`M:inject_handoff_files(agent_name)` автоматически добавляет критические файлы (из плана, зафиксированные, запрошенные) в историю следующего агента, если они там отсутствуют.

## 7. Примеры Использования

### Инициализация
```lua
local ctx = require("context_flow").new(flow_config, full_config)
ctx:add_file("main.c", "int main() {}")
ctx:pin_file("main.c")
```

### Сборка промпта
```lua
local prompt_data = ctx:build_context("coder", coder_cfg, 8000)
-- prompt_data.messages готов для отправки в LLM API
```

### Обработка ответа
```lua
local result = ctx:process_turn_response("coder", raw_llm_output, executor)
if result.type == "EXECUTED" then
    -- Команда выполнена успешно
end
```
